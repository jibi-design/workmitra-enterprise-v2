4. Admin structure

Final admin decision:
Use one central admin portal:

admin.mitralabs.app

Inside this one admin portal, every product must have its own separated admin area.

Admin portal structure:

admin.mitralabs.app
- Super Admin Dashboard
- Mitra Labs website admin
- Job Mitra admin
- HomeFix Mitra admin
- Future app admin
- Future website admin
- Reports
- Users
- Roles and permissions
- Audit logs
- Settings

5. Admin role rule

There must be a Super Admin.

Super Admin:
- Can see and manage all products
- Can manage all admins
- Can manage global settings
- Can view audit logs
- Can control permissions

Product Admin:
- Can manage only assigned product/app
- Example: Job Mitra admin can manage only Job Mitra
- Example: HomeFix Mitra admin can manage only HomeFix Mitra

Website Admin:
- Can manage assigned website content only
- Example: Mitra Labs website admin
- Example: Job Mitra website admin
- Example: HomeFix Mitra website admin

Support / Moderator:
- Can review reports, users, complaints, and support issues only where permission is given

Important:
One admin portal, but each app/website admin must stay separated.

6. Public app rule

Admin must not be inside public mobile apps.

Do not add Admin inside:
- Job Mitra public app
- HomeFix Mitra public app

Correct:
admin.mitralabs.app

11. Future Google Cloud migration

Future migration is possible.

Current:
Node.js backend on Render
PostgreSQL database on Supabase

Future:
Node.js backend on Google Cloud Run
PostgreSQL database on Google Cloud SQL

Reason migration is possible:
Both databases are PostgreSQL.

Important rules for easy migration:
- Use standard Node.js backend
- Use PostgreSQL properly
- Use Prisma ORM if possible
- Do not hardcode secrets
- Do not depend too much on one provider-specific feature
- Keep business logic in backend, not frontend
