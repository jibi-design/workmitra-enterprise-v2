## 1.2. Purpose

Full Insights is the future hidden analytics and decision-support architecture of Job Mitra.

Insights summary may be launch-visible as a small support/dashboard surface.

Full Insights is hidden / non-launch and must not be represented as launch-active analytics.

It exists to prepare a clean enterprise-grade analytics foundation without exposing private data, Admin risk signals, HR records, Workforce Ops internals, payroll-like reports or misleading analytics claims.

## 1.3. Core Principle

Launch Insights = safe summary only.

Full Insights = hidden future analytics and decision-support architecture.

Full Insights must remain:

- role-safe
- privacy-safe
- domain-separated
- trust-aware
- data-confidence aware
- action-oriented
- not misleading
- not exposed as launch truth
- separate from Admin enforcement
- separate from payroll/legal reporting

## 1.4. What Full Insights Is

Full Insights is:

- hidden in launch UI
- future analytics architecture
- domain-level decision-support layer
- trend and signal interpretation system
- role-separated reporting layer
- future bottleneck detection support
- data confidence and insight-quality layer
- permission/audit-aware export-ready architecture where future-approved

## 1.5. What Full Insights Is Not

Full Insights is not:

- launch-visible full analytics
- public performance scoreboard
- employee surveillance dashboard
- employer spy tool
- payroll / legal reporting authority
- Admin enforcement system
- social ranking feed
- replacement for trust moderation
- replacement for Employer Trust Visibility
- hidden Admin risk dashboard for normal users

## 1.6. Hard Non-Mixing Rule

Full Insights must not be mixed with:

- launch-visible Insights summary
- Admin moderation
- Employer Trust Visibility
- Work Vault private data
- HR Section records
- Manager Console notes
- Workforce Ops operational truth
- payroll / legal reports

Rule:

Summary cards may show safe high-level information.

Full analytics must remain hidden until future approval.

## 1.13. Advanced Full Insights Protection System

This section adds the enterprise-grade future insights layer.

It is hidden for launch and may only be activated in a future approved version.

### 1.13.1. Role-Safe Insight Dashboard

Role-Safe Insight Dashboard ensures every metric is shown only to the correct role.

Rules:

- employer sees own employer-owned insights only
- employee sees own employee-owned insights only
- Admin analytics stays inside Admin System
- hidden HR / Manager / Workforce metrics stay hidden until approved
- cross-user comparison must not expose private data

### 1.13.2. Actionable Insights, Not Just Numbers

Insights should help users understand the next safe action.

Examples:

- improve profile
- review pending applications
- complete rating
- check Work Vault readiness
- review stale offer
- update job detail

Rules:

- action prompts must open allowed launch-visible screens only
- action prompts must not expose hidden domains
- action prompts must not force irreversible actions
- action prompts must remain simple and non-noisy

### 1.13.3. Data Confidence Label

Data Confidence Label helps users understand insight reliability.

Allowed labels:

- local_demo
- low_data
- enough_data
- backend_verified_future
- unavailable

Rules:

- Phase 0 must show local/demo or limited confidence honestly
- low-data insights must not be over-interpreted
- backend-verified label must not appear before backend implementation
- confidence labels must be readable and non-technical

Safe wording:

```txt
This insight is based on available local app activity.
```

### 1.13.4. Insight Privacy Filter

Insight Privacy Filter prevents private data leakage.

Must protect:

- Work Vault private documents
- employer internal notes
- Admin risk signals
- HR records
- Manager Console notes
- Workforce Ops operational internals
- payroll future data
- other users’ private activity

Rules:

- insights should summarize safely
- private records must not be exposed as metric detail
- source record links must respect permission
- hidden domain metrics must stay hidden until activation

### 1.13.5. Trend + Bottleneck Detection

Trend + Bottleneck Detection identifies stuck or weak workflow areas.

May detect:

- stale applications
- low applicant response
- low offer response
- pending ratings
- incomplete Work Vault
- repeated no-response
- unresolved lifecycle closure
- carry-forward trend where future Workforce Ops is active

Rules:

- detection is guidance only
- detection must not punish users automatically
- detection must not expose hidden Admin risk logic
- detection must not become public ranking

### 1.13.6. Insights Export Boundary

Future export may exist only with permission and audit.

Export may include:

- safe employer-owned summary
- safe employee-owned summary
- role-safe aggregate metrics
- non-sensitive summary

Export must not include:

- private Work Vault documents
- hidden Admin notes
- HR internal notes
- Manager private notes
- Workforce Ops hidden internals
- other users’ private data
- payroll/legal reports unless future payroll system approves it

Rules:

- Phase 0 must not claim real export unless implemented
- future export requires backend, permission, audit and privacy review
- export actions should be audit logged
